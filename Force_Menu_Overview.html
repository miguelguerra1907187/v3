Trouble bill helper

Force Menu — Features & Scenarios

A keyboard helper for trouble bills. It writes the FORCE 1 / FORCE 2 notes in the standard wording and enters them on screen with the same clicks and keystrokes a person would use. The clerk always reviews and saves every note.

Why Why this improvement is needed
Every trouble bill needs the same routine: a force note in the ERP (Special Instructions), a search of the bill number on Page 1 — and on Page 2 for hazmat, to see the terminal — and an informational note on Page 1, often with a "Hold at term ### DUE TO ..." text. Done by hand, that is the same copy, paste, switch window, search and type, dozens of times per shift.
✗ Repetitive
The same steps on every bill
Copy the number, switch windows, paste, search, open the note screen, choose the type, type the note. Every time.
◑ Inconsistent
Wording changes from person to person
Free-typed notes vary. The menu always produces the same standard wording for the same issue.
✗ Easy to get wrong
Small mistakes are costly
A typo in the terminal, the previous bill's note pasted again, or the search showing the previous number are easy to miss when working fast.
✓ With Force Menu
A few keys, then review and save
The clerk picks the issue; the tool does the clicks and typing; the clerk checks the result and saves it personally.
Overview What is this tool?
01
Opens with one key
Press Del and the menu appears over the current screen. Press it again and it closes. Nothing else stays open on screen.
02
Choose by elimination
Pick FORCE 1 or FORCE 2. From then on only that type's issues are shown, and inside an issue only its own options.
03
Combine several reasons
Several options can be marked with the numeric keypad. Each one is written once, separated by commas: f1-missing page with breakdown,po.
04
Writes the ERP note
Opens Special Instructions, types FORCE1 or FORCE2 and the note, then stops with PRESS ENTER. The clerk reviews and saves.
05
Looks up the bill
After the clerk saves, it copies the bill number, closes the bill and searches the number on Page 1 — and on Page 2 for FORCE 2 or a hold.
06
Asks only for the terminal
For a hold, the clerk types just the terminal number. The tool builds the full "Hold at term ### DUE TO ..." text.
07
Writes the Page 1 note
Opens the notes screen, chooses Informational, pastes the note and stops with VERIFY AND SAVE.
08
Shows how long it took
The final message includes a small line like F1 OK IN 6.4 S — only the automatic part, not the clerk's own time.
Section 1 The two note types — FORCE 1 and FORCE 2
FORCE 1 covers missing or unreadable information. FORCE 2 covers hazmat and always carries a hold with a terminal. A FORCE 1 also carries a hold when the issue is with the consignee.
F1 · FORCE 1
Missing or unreadable information
Shipper info · consignee info · missing page (with breakdown, po, special instructions) · number sticker covering a field (bol, po, quote, weight, reference num, class, nmfc, hu) · illegible (same fields + accessorial and special instructions).

✗ Scenario F — Something does not respond
Stops and says where
If a window is not found or a step does not respond after its retries, the tool stops, removes DON'T MOVE and shows where it stopped. Nothing is saved; the clerk simply finishes that bill by hand.

Safeguards Built-in protections against errors
Waits for the screen, not the clock
Never types before a page is ready
Before each click it notes how a small area of the screen looks, and continues only when that area has changed and stopped moving — the same way a person sees that a page finished loading. If a page is slow, it waits longer instead of typing too early.
Click → page loading…
Area changed and is still → continue
Slow page → keeps waiting (up to 2 extra sec)
Retries before giving up
Copying and typing the number are checked
If the bill number did not copy, it selects the whole field again and retries (up to 3 times). On Page 2 it checks that the number really appeared in the search box; if not, it clicks and types it once more.
Copy empty → select field again → copied
Number not visible → click + type again → OK
Types the number
Avoids searching the previous bill
The search box on Page 1 sometimes kept the previous number when it was pasted, even by hand. The tool types the number key by key instead, so the page always searches the new one.
The clerk stays in control
Review and save is always manual
The tool never presses Save, never pastes the same note twice and never continues after a stop. Each sequence ends on a message that asks the clerk to verify.

The first screen also lists the last notes used in the session; pressing 3, 4 or 5 copies one of them again. They are kept in memory only and are cleared when the tool closes.
Security Local only — no data enters or leaves the machine
Force Menu works only with the windows that are already open on the clerk's screen, using the same clicks, keystrokes and copy/paste a person uses. It has no network code of any kind — no web requests, no connections to servers or databases, no cloud. The bill number is held only in memory while a sequence runs and is never written to disk.
No network activity
Zero outbound or inbound connections
The script contains no networking calls at all — it cannot send anything out or bring anything in, even by accident. It does not touch the ERP's or the pages' data directly; it only works through the screen like a person.
No sensitive information stored
Only step names and times are written
The only files it writes are timing logs: step names, milliseconds and character counts (for example "number copied (9 characters)"). They never contain bill numbers, terminals, customer names, addresses or note text.
Screen check: colors only
Compares colors, reads no text, saves nothing
To know when a page finished loading, it looks at a small area of the screen and compares its colors in memory. No image is saved, no text is read, and nothing is kept after the comparison.
No installs, no admin rights
One PowerShell script, already part of Windows
Nothing is installed, no services or scheduled tasks are created, and no administrator rights are needed. It does not modify the ERP, the pages or any company file. Closing it leaves nothing running.
Only its own keys
Not a keylogger
It only checks whether its own shortcut keys are pressed — plus Enter / Alt+O while it waits for the clerk to save. It does not record or store anything that is typed.
Standard Windows functions
Same permissions as any desktop utility
Moving the mouse, clicking, pressing keys, bringing a window to the front and reading a key state are ordinary, documented Windows operations — not privileged and not intrusive.
